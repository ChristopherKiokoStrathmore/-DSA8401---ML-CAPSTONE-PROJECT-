# Technique justification

One row per syllabus area in the DSA 8401 brief. Exclusion is a decision, not a missing section.

| Syllabus area | Decision | Why |
| --- | --- | --- |
| Classical supervised learning | Used | Majority class per head, an emergency keyword heuristic, and TF-IDF (word and character n-grams) plus logistic regression with `class_weight='balanced'`. `C` is chosen on the validation split only. These are the CPU baselines every later model is compared with. |
| Unsupervised learning | Excluded as a model; near-duplicate grouping is used | Issue, sentiment, and urgency already have labels, so clustering would not decide the classes. Character 3-gram MinHash plus a Dice check assigns `dup_group_id`. Splits are grouped on that id, and `tests/test_no_leakage.py` fails if a near-duplicate crosses from test into train or validation. |
| Deep learning | Used | AfroXLMR-base (`Davlan/afro-xlmr-base`), a 12-layer XLM-RoBERTa adapted on African languages, including Swahili. The proposal's large model froze 8 of 24 layers, which is the bottom third. This run freezes the bottom 8 of 12 plus the embeddings, and trains the top 4 layers and the heads, so the same fraction stays trainable. Base rather than large is the deviation: base is about 0.3B parameters and fits one Colab T4 in fp16 in about 60–90 minutes; large is about twice that and does not. Three heads share the encoder: issue softmax (10), sentiment softmax (2), and urgency CORN (3 ordinal levels). CORN trains the conditional events P(y > low) and P(y > medium), which respects low < medium < emergency instead of treating urgency as unordered. Masked loss means a row contributes only for the heads it has labels for, so the 1,500 issue/sentiment texts and the 868 urgency texts can share a batch. Class weights counter the small issue classes. Urgency row weights keep the 688 Groq silver rows from equalling the gold rows. One seed, 42. Early stopping and the emergency threshold use validation only. |
| Generative AI | Excluded from serving; used offline for silver labels only | An LLM in the request path was ruled out for cost, because customer text is PII, and because a reviewer cannot re-run a hosted model bit-for-bit. Gemini relabelled `gemini_relabeled.csv`, which is excluded from training. Groq distilled the 688 urgency silver rows that are in the training file with a lower weight. No LoRA, RAG, or agentic loop. |
| Feature engineering | Used, except SHAP | PII masking with the four training tokens, channel and type normalisation, word and character n-grams, and the leakage audit above. SHAP was not added. The evaluation already reports per-class precision, recall, and F1 with support, plus a 30-row error file with a category hint. That is the error analysis this dataset can support tonight. |
| Monitoring and fairness | Excluded tonight; stated as future work | Drift monitoring (for example Evidently) needs a second time window and a deployed scorer writing logs. Neither is in this submission. A language or code-mixing breakdown was a later plan item and is not computed here. Subgroup fairness is future work once those tags exist. |
| MLOps extras | Used in part | Pinned `requirements.txt`, YAML config, epoch checkpoints with resume, SHA-256 on the saved state dict, Makefile targets, Docker with a non-root user and a healthcheck, and `MODEL_BACKEND=tfidf\|transformer` so a reviewer without a GPU still gets predictions. MLflow and a model registry were not added; the artefact directory plus the hash file is the registry for this submission. GitHub Actions is not wired in this repo. |

The emergency threshold is not a training hyperparameter. On the urgency validation split only, it maximises emergency recall subject to a false-emergency rate of at most 0.20. Ties prefer the lower false-emergency rate, then a higher threshold. That one number is then applied to the test split. Test labels are not read while `C`, early stopping, or the threshold is chosen.
